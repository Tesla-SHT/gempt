# GemPT v0.6.1
- 使用 `gempt_gempt` MCP 的 `gpt_run(goal,cwd,access="change"|"inspect",workspace="inherit"|"share",session_id?)`、`gpt_ask(goal,file_paths?,cwd?,session_id?)`、`gpt_ctl(action="status"|"steer"|"interrupt"|"reply",run_id?,message?,call_id?)`。
- 委派时沿用当前 Gemini 家族的配对。已知家族时可传 `gemini_family="hydrogen"|"neon"|"carbon"`，杂活咨询传 `tier="chore"`。
- `gpt_run` 异步直返 `wait_command`（如 `gempt-wait <run_id>` 或含绝对路径的后备命令），优先原样用 `run_command(WaitMsBeforeAsync=500)` 后台等待唤醒；严禁循环轮询 status。
- 多路并发改同一 Git 仓库时 `gpt_run(access="change", workspace="share")` 隔离 worktree（基于 `HEAD` 检出；只读 `access="inspect"` 禁止配 `workspace="share"`）；续聊传 `session_id` 保缓存；失败返工省略 `session_id` 开新线程。
- Magpie 面板提供 5 档工作分工（0% 关闭 / 15% 重活提示 / 35% 源码写转 GPT / 60% 源码写 + 每回合 5 步核实止损 / 80% 入口直派 + 2 步核实）；80% 档计入 Gemini 前端编排约 15–20% 的占比下限。视觉、SKILL、brain 与用户明示“自己改/查”始终由 Gemini 处理。
- 在侧边栏打开 [GemPT](sidecar://gempt/gempt_live/) 实时看流与介入，也可用 `gpt_ctl` 查询和控制。纯编码工作区优先直接使用 Codex CLI。
- 默认通过 AGY 原生 Swarm 委派代码与执行任务。先用 `swarm(action="title")` 命名，再用 `swarm(action="add")` 创建工位，按 `swarm_pane` 在 `plan.json` 登记工位任务。模型取 `routing_policy.swarm_shell_model`（默认 `gemini-4-hydrogen-low`），写入用原生 `workspace="share"`，检查用 `"inherit"`。快速 `gpt_ask`（含 `tier="chore"`）和 `gpt_ctl` 可直调。用户明确要求「不用 swarm」时可直派，控制台也可关闭 `native_swarm`。brief 让工位从 stdin 把任务交给 `gempt run --cwd "$PWD" --workspace inherit --tier <tier> --host <coordinator_id> --title <name> --goal -`，再后台执行回执的 `gempt-wait` 命令。看板新消息用 `gempt steer <run_id> <message>` 转达，后续回合用 `gempt run --session <session_id>`。将 `ask_gemini` 发到看板，收到答复后用 `gempt reply-tool <run_id> <call_id> <text>` 续跑。Gemini/Claude 工位按需原生拉起。Codex 默认执行预算为 3600 秒，等待 `ask_gemini` 回复期间暂停计时。
